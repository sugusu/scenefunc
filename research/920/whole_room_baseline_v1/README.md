# 整屋固定目录基线：日内瓦开发壳

研究主问题仍是：从真实项目学习“在这些条件下为什么做这个动作”，是否能改善未见房间。这里先建立完整房间的冻结底座参照。单房间的接口修正、普通反馈或资产补齐，不计入训练收益。

起点为同一研究者重建的空壳与16项真实静态资产。外壳尺度来自已发表完成后示意，竖向尺寸和门开状态明确是假设；这不是测绘改造前原房。日内瓦已在派生前划作开发家族，不能用于封存测试。Builder看到住户需求的有来源改写、未知项、原生对象与资产表、工具和实际五视图；未获得发表家具位置或专业解释。

- WHOLE-v1（191014Z）：事前冻结24回合上限；首个模型输出达到1024 token且无EOS，12完整动作块及一残缺块，工具执行0。保留失败。
- WHOLE-v2（191710Z）：另行冻结完整单工具块的停止准则，固定同一权重、任务、目录与24回合上限。模型每次产生一个完整编辑，引擎返回真实状态再观察。不是从v1截断输出提取动作，也没有训练。

每轮保存精确模型请求、图像哈希、原始生成token、终止原因、计时与显存、实际工具回执及可恢复检查点。查询或拒绝也消耗工具预算，生成达到长度上限而未形成可接受终止的文本不执行，不静默重抽。24次是上限，不是必须耗尽；模型无动作结束、协议失败或资源上限均保留真实结局。

目前只使用本机固定底座推理及原生工具。动态炉门、盖板、折叠屏风、建筑分隔墙、卫生间围护、管线、热源和排风没有验收；不能用本轮结果跨越这些能力边界。独立设计师对本次候选的评价仍没有取得。公开项目的设计理由是来源证据，不冒充对生成房间的真人复核。

下一判断以终态事实为准：首先确认是否形成有必要功能的房间，以及普通工具/反馈能修复什么。只有多个独立项目中仍出现可信的用途取舍问题，且同项目理由、可执行动作和后果具备来源，才进入理由—动作配对数据审查。训练仍须另行审定，PAIR加载器验收不能替代此项授权或数据资格。
