# 在 Scene-Designer 上学习真实项目中的室内设计决策

更新：2026-11-04。依据用户本轮给出的总体架构与算法修正研究主线。本文件定义长期研究目标；训练须单独审定，巴黎 P920-DD-v1 是底座验证。

## 总目标与可证伪问题

从住户用途和实际房间条件出发，生成完整、可编辑、能支持这些活动的三维房间。研究模型能否把真实项目中的专业经验，落实为适用于当前条件、对象和场景状态的设计决定。

核心假设：在学习相同专业理由和相同动作的条件下，将理由与对应项目、状态、可编辑对象和动作正确配对，是否比分开学习，更能改善未见房间的硬需求满足、整屋设计质量和返工成本？充分提示、同知识检索、几何及用途反馈均须作为有竞争力的参照。工程修复或普通反馈收益不能折算为训练贡献。

**独立设计项目是采集和划分单位；有来源、可重演的决定是训练单位；完整房间是最终评价对象。** 单张桌面或巴黎单题改善不能代替整体目标。允许共桌、分桌等不同可行解；能同时保留材料与餐位的大桌也可能满足持续占用要求。

## 一、从需求到完整房间的系统

1. **框架与权重。** 采用 Scene-Designer 的工具动作、场景状态、多视图观察和建设／评审任务格式。初始权重为公开 SFT 阶段的 Scene-Builder-Qwen3-VL-8B-Instruct，固定 revision `63e235a0c0d6e5bc2f8f3485214df4457fd2e672`。保留 SceneSmith 在原框架中的执行分工；房壳、家具、墙面、天花的分阶段生成服务完整创作。巴黎受控比较固定房壳，只检验家具阶段。当前本地桥接代码不等于已实现完整上游系统。
2. **需求表示。** 始终保留住户原话，借鉴 Function2Scene 整理使用者、活动、时间关系、须保留的对象、可协商偏好与未知项，以住户能理解的“什么地方发生什么活动、哪些东西不能动”表达要求。从实际平面／房壳绘制带比例的需求图，标明门窗、已有物体及用户确实指定的区域；用活动小图表达先后或同时占用。未指定位置的活动留给设计，用户事实与研究者尺寸假设分开标注。不得泄漏参考家具坐标或事后设计解释。巴黎 A/B 共用同一需求卡，仅冻结文本中的材料条件不同；等信息文本与图文比较另列消融。
3. **建设闭环。** Builder 每步读取原始任务、需求卡、当前对象表、实际工具、最近回执与观察，提出资产请求或一个可执行编辑。引擎返回真实资产和变化，更新俯视加四个斜视图。借鉴 SceneWeaver 按问题选工具：净空量测回答占用，视图检查遮挡，不能让同一种视觉判断包办全部证据。任务完成或预算用尽时导出完整终态。保留对象 ID、资产 ID、位姿、状态差异、动作与回执，另导出可查看、可编辑的三维结果。
4. **专业评审。** 建设与评审共享同一底座的任务格式。评审指出具体对象、受损或改善的活动、支持判断的证据与未知量，执行结果由独立程序或人工核验。先分别离线评价建设与评审，再单独测评审指导生成的收益；评审重排与单次生成分别报告。

## 二、真实项目数据与监督

优先采集取得研究使用权的原始任务书、改造前后平面／模型、设计师说明与独立复核。资料不足时只使用证据能支持的部分，不从成品照片臆造采纳理由。每案登记来源、作者、使用权限、项目家族、原始需求、研究者改写、初始空间与已知尺寸。

先按项目家族划分训练、开发和封存测试，再派生动作、视图与比较；同源改写和同项目变体不得跨集合，检索库亦与测试隔离。测试项目的事后解释和评分专用真值不得进入推理输入。

| 决定的组成 | 证据与使用规则 |
| --- | --- |
| 条件及证据 | 提取对象身份、活动、限制与尺寸；用户输入只含设计开始时可得的信息。 |
| 专业理由 | 记录作者解释、涉及对象及适用条件；独立设计师复核时记录身份角色、结论与分歧，不把研究者推断标成专业真值。 |
| 动作与后果 | 映射至实际工具，在初始场景回放，保存每步响应、状态差异、关键阶段与完整终态。研究者重建顺序明确标注；不支持的饰面／内部构造等保留未知。 |
| 建设样本 OTA | 按上游格式组织观察与动作；关键步以有依据的短设计说明监督需保护与可改变的内容，再预测工具及参数；其余步骤保留合法动作示范。 |
| 评审样本 OTC | 从同一起点构造可执行候选并渲染。实测差异给功能标签；美感、舒适与专业取舍由独立设计师在相同任务下比较，允许并列或无法判断。构造候选与历史真实否决方案分开登记。 |

建立知识覆盖账：分区、流线与人体使用、可变活动、视线采光、收纳与既有资产、色材照明与氛围、造价施工和维护。每类注明可用项目、可核动作、结果依据与空缺。教材／指南给一般原则及适用范围，项目给真实取舍，几何工具给量测，住户给偏好，四者不能相互冒充。

用户提供的育儿房原柜案例说明身份保留问题：保留旧柜与删后重建可能具有相同几何哈希，却只有前者保留原实例。合格样本须在初始对象表中给出原柜 ID 与可改属性，终态检查原 ID；未重建的手绘柜门或未知容量不计为模型成果。原始采访、工程对照和哈希仍须在 920 逐项核验，不因收到案例说明而假称本机已验收。

附件提及的知识卡、住宅图片、开发三维房间与二维评审样本只构成待核验清单；数量、许可、项目对应关系和专家认可尚未在本轮核实。首项数据里程碑是一条证据完整、可回放的同项目决定，不是拼接无对应关系的文本与动作。

## 三、拟验证的训练算法（训练须单独审定）

优先采用官方 SFT 入口及可选 LoRA，在固定 Scene-Builder 上有限适配；采用适配器路线时冻结原权重，仅更新适配器。以教师强制对助手输出的动作序列或评审答案计算 token 交叉熵。输入、工具回执及评分专用真值不作为预测目标；专业理由只监督真实项目可支持的部分。推理中模型自行决定，始终可见原始任务，不提供测试项目设计师的事后理由。

**实际加载器验收先于训练申请：** 用同一小批可信项目样本检查真实训练入口产生的上下文、标签与 loss mask，证明配对确实改变示范上下文或受监督 token。保存来源映射、可比较样本与 token 统计；不能只改 JSON 标签却训练相同序列。此验收不进行参数更新，通过后再提交训练方案供单独审定。

| 对照 | 学习材料与角色 |
| --- | --- |
| 相同材料分开学习 | 同一批专业理由和同一批动作分别组成案例解释实例与场景动作实例。 |
| 正确配对学习 | 把同一项目、同一状态下的理由、可编辑对象及动作放在一个训练实例。 |
| 普通动作微调 | 检验收益是否仅来自动作适配；同样须另行审定训练。 |
| 冻结底座与充分提示 | 给足原始需求和合法工具信息，测普通提示能解决多少。 |
| 冻结底座与同知识检索 | 使用相同的其他项目知识与案例，隔离训练收益和获得知识的收益。 |
| 冻结底座与几何／用途检查 | 使用独立量测反馈，检验无需配对学习即可取得的收益。 |

两核心组都能使用相同的其他项目案例，尽量匹配受监督 token 数、动作示例数、更新步数及运行预算，报告无法完全匹配的差异。固定模型、工具、资产与推理预算；配对关系是核心自变量。若配对有可重复增益，再比较显式输出理由和直接输出动作。评审重排与每次只生成一个房间分别计分，首轮无须 GRPO。

拟检验的贡献是“知道一条专业经验在什么条件下对应哪项设计动作”。例如分时共用节省面积，须结合持续占用条件、实际空间和可行替代方案才能决定是否采用；不要求模型一律选择预设家具数量或参考布局。

## 四、独立评价与论文验收

1. 核验官方实现与相关工作，明确可证伪假设、创新边界和适用范围。独立房间中存在多个可行方案、普通反馈仍反复损害用途，且有可信同项目证据时，才列为训练对象。
2. 查看封存测试结果前冻结项目划分、种子、预算、主指标、基线、消融与停止规则。样本规模根据独立项目数、主指标方差及研究主张确定，不把同房间视图或种子当独立项目。
3. 独立程序验实际网格、对象身份与硬需求，真实独立设计师做整屋盲评；报告返工、成本、失败动作、副作用和未知项。验证量测器，记录研究者阈值及敏感性。unknown 不算成功，删除必需家具带来的碰撞下降不自动算设计质量提升。
4. 区分资产检索、工具执行、建设、评审和评审引导生成；报告单次生成与候选选择的不同预算，不把普通反馈改善写成训练改善。
5. 交付可复现的方法、代码、数据来源／许可／哈希、运行命令与配置、真实启动及退出记录、主结果与公平消融、统计不确定性、可分享三维结果及图表、完整论文草稿、失败分析与复现附录。干净检出后复核关键证据，每项主张对应可检查产物。
6. 完成内部证据审阅且上述标准满足后才标记研究完成。不能保证录用；假设不成立时如实报告，不能挑样本、放宽验收或隐藏失败。准备 Goal 文本或完成开发诊断不等于研究完成。
