# 独立整屋评价协议草案

2026-11-04；状态：**草案，未冻结、未开始正式评测**。已登记的 9 个来源项目家族均不自动构成合格样本；已用于来源审阅或调参的家族不能进入封存测试。当前封存项目数、人评参加者、样本量依据和训练审定均未就绪。已有真实原生房间导入、固定目录家具构建、五视图及检查点恢复；完整可用住宅仍未验收，建筑围护／材料／关节等能力不齐。本文把总体研究问题落实到可审查的评价单位、证据和比较方式；不把已知巴黎结果改写为新实验。

## 要回答的问题与比较单位

主要问题：同一批专业理由和动作经过正确同项目配对学习后，能否提高新项目中完整房间的硬需求满足，并在整屋盲评与返工方面取得有实际意义的改善？物理项目家族是划分与统计聚类单位；任务是固定房壳和需求组合；运行是方法、任务、种子和预算的一次尝试。视图、动作、同项目改写和种子不是独立项目。

保留两个不同问题：单次建设的效果，以及额外候选生成／评审选择后的效果。前者每次交付一个最终房间；后者须另计所有候选、评审和执行成本。在学习对照之前，先确认多个布局确实可行，且充分提示和普通量测反馈仍有稳定、可核的用途损害；否则保留普通反馈解决问题的结论，不以它证明训练必要性。

## 冻结前必须形成的清单

- 按项目家族确定 train/development/sealed_test，登记来源关联和同源改写。派生样本、视图、检索条目之前固定划分。查看过目标设计并参与调参的项目不得回填为封存测试。
- 每项任务保存设计开始时可获得的事实、原始需求、所有研究者假设、初态、可动对象、资产范围、活动状态／切换关系和硬需求。无位置要求的活动不指定参考坐标。
- 硬需求表提前指定适用状态、核验方法、测量容差、unknown 条件和依赖证据。人体尺寸、活动包络、通道宽度、同时使用人数等不能事后为某个输出调整。
- 在看封存结果前固定方法、种子、模型／工具／资产版本、输出／工具／反馈预算、失败处置、评测器版本、主指标、次指标、统计方法和停止规则。全方法共享原任务与可用工具。
- 独立设计师评审的资格、人数、任务分配、报酬／同意与信息展示方案须落实；本项目未邀请或联系任何评审者。

样本量须基于独立项目数和预先定义的最小有意义效应，结合不进入封存测试的开发数据估计方差或做功效模拟。当前没有足够专业项目估计它，不能写成已确定的样本规模。若资源只支持少量项目，预先限定为探索性结论并报告不确定性。

## 硬需求和活动证据

每个要求 × 活动状态记录 `pass / fail / unknown / not_applicable`，并绑定任务版本、场景状态哈希、对象／资产 ID、评测方法与证据文件。`not_applicable` 的条件须由任务清单预先确定；模型不能通过删除对象或漏交状态让要求消失。任何必需项 unknown 都不能计作已验证成功。

| 核验对象 | 需要的证据 | 不能单凭什么下结论 |
| --- | --- | --- |
| 已有资产保留 | 初始和最终原生实例 ID、资产绑定及允许变更记录 | 同名、同形、几何哈希相同不证明原实例仍在。 |
| 物体和活动空间 | 实际资产几何、姿态、任务规定的接触／可用区域，以及独立测量 | 整体包围盒不等于可用桌面或可使用内部容量。 |
| 通行与进入／使用 | 门窗／门扇、固定障碍、使用位置与路径连通；任务所需尺度和活动包络 | 图上“看起来有空隙”或静态无碰撞不证明可通行。 |
| 先后活动切换 | 各状态可用性；移动哪些实例、放到哪里、移动后对其他活动的影响；复位过程 | 单张终态图不能证明变换可执行。 |
| 同时活动 | 同一状态下同时存在的使用区域、材料、人数和操作空间 | 两个活动分别有一个可行状态不证明能同时发生。 |
| 视线、采光、饰面和氛围 | 分别使用可量测视线／照明条件与独立专业评价，标明所缺光学和材料信息 | 同一 VLM 判断不能替代所有独立证据。 |
| 完整、可编辑交付 | 原生状态可恢复，ID 和资产引用齐全，实际三维结果可打开，所有要求及未实现部分有记录 | 家具数量、GLB 存在或渲染成功不等于完整可用房间。 |

活动切换候选的评估需要同时看“活动状态”和“家具停放状态”，另查移动路径、物体可移动性及复位成本。若只有代理尺寸，结论限于该代理模型。原柜候选则分别核验身份保留、外观改动与储物功能；未知内部结构不以几何相似补齐。两者只用于协议开发，不作为独立测试收益。

## 指标及失败处理

主客观指标分开报告，不先合成一个任意加权总分。

1. **整屋硬需求已验证成功率。** 对每个计划运行，完整交付且所有必需状态／切换的硬需求均 pass 才计 1，否则计 0；同时单列 fail 与 unknown。先在项目内按预先固定的任务／种子权重平均，再对项目家族等权平均，避免案例多的项目主导结果。
2. **整屋盲评。** 在相同任务下比较两个完整交付，允许 A 更好、B 更好、并列、证据不足。评审者看到同等信息量的匿名场景、统一视图及必要活动切换记录；隐藏方法、训练条件和研究者预期。另给用途、整体协调与返工需求的分项理由，并要求指认对象和证据。
3. **返工与成本。** 记录达到预定验收所需追加合法编辑、人工时间、模型输入／输出 tokens、工具尝试、失败动作、渲染次数、墙钟时间和资源成本。未完成者不伪造“完成所需次数”，报告预算内完成比例与未完成状态。
4. **副作用和未知。** 指标按要求类别细分；报告保住目标功能但损害睡眠、餐位、通行、既有资产等的情况。未知率独立列出，不能藏进平均分。

计划表中的所有运行均进入结果表。解析失败、工具拒绝、截断、资产失败和预算耗尽保留原输出、实际退出与最后可核状态。执行器无声回退或删除失败样本均不允许。失败后保留初态或最后状态的规则在运行前确定；该状态仍可测量，但“未改进且保留基线”与成功完成设计分别报告。发生与方法无关的基础设施中断时，按事前规则恢复同一运行；重试和额外成本不得隐藏。

## 公平学习与推理对照

核心组只改变专业理由与状态／动作是否在同一训练实例中对应；两组保有相同来源、理由和动作。先按决定建立逻辑训练单元，再检查真实加载器产生的监督 token、动作次数、样本数和优化步。分开组的理由与动作两条序列可组成同一逻辑单元；不能仅匹配 epoch 数而让优化次数加倍。旧 DATA 工程协议实测为 84 对 92 tokens、1 对 2 样本，原记录保留。后续 [PAIR-v1](../../../runs/920/P920-PAIR-v1_20261104T174408Z/README.md) 将两组各组织为一个决定、两个样本：同样 32 个理由目标与 51 个动作目标，共 83 个监督 token，10 个图像实例。未填充输入为 2630／2601，固定填充不是 FLOP 公平证明；[ENTRY-v1](../../../runs/920/P920-ENTRY-v1_20261104T204327Z/README.md)已在实际官方CLI/DataLoader接通两种数据并完成dry-run；可信专业样本、Trainer/model loss和优化步仍未验收，因此不能用于宣称学习效果。

训练方案须明确结构包装 token 如何计 loss、各任务权重、组内采样和梯度累积，以及最终无法消除的预算差异。不得通过增加无关文字宣称信息或 token 公平；任何 loss 或采样器改动先在真实入口核验，再单独申请训练。用动作微调、冻结底座的充分提示、同知识检索、几何／用途反馈作参照；检索库排除同项目和封存测试信息。若使用评审重排，额外预算和独立评审质量另报。

## 统计与解释

主要报告配对的项目级差异与区间，并展示每项目结果和未知率。计划采用以项目家族为单位的成对重采样：一次抽中某家族时保留其全部方法、任务、种子和评审关联；不得把同项目视图当额外样本。若独立项目过少，区间和检验不足以支持稳定的总体结论，直接限制主张。具体重采样次数、随机种子、区间算法及多重比较处理须在冻结配置中确定。

盲评同时报告四类结论的比例及评审分歧。证据不足不换算成平局；如计算偏好得分，必须并列报告有效覆盖率和预先规定的 unknown 敏感性分析。仅在可判断子集胜出不足以说明整体更好。

评测器本身先用独立人工／程序复核，包括正例、已知损害和边界情况；这些校准场景留在开发集。对研究者设定的几何阈值报告预先指定的敏感性范围。主张须分别对应建设、评审、评审指导生成、训练收益与跨项目泛化的证据，不能互相替代。
