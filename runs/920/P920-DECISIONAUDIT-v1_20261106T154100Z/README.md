# 决定监督的条件覆盖与候选修正

本批完成对实际22步、44份训练文档的逐项核对，另补2条“恢复活动模式”的研究者应用注释候选。没有新增模型调用、训练更新、场景执行或独立项目。已完成试验仍是7个决定位置、6条原则，不能用新候选回改旧计数。

## 核实后的判断

多数输入确实保留了布局选择，不能把失败概括为“所有答案已指定”。不足在于可选策略和决定监督的覆盖不均。

| 原监督位置 | 可以判断什么 | 未覆盖的选择 |
| --- | --- | --- |
| AIR挂衣 | 为短住用途选择资产与摆位 | 目录只有开放挂杆这一衣物专用资产，未给合理封闭衣柜同等机会 |
| Guilbault加柜 | 三柜布置与集中布局 | 柜数由任务给定；与编辑例同家族，不增加独立项目 |
| Guilbault移柜 | 三柜之间的重新组织 | 仅一个重建布局序列，没有另一条件下的决定监督 |
| Paper移桌 | 活动阶段改变时腾出声明预留区 | 回到日常用餐的步骤只有动作监督 |
| Waterloo合桌 | 在有限可编辑对象内形成共享工作面 | 恢复独立工作步骤只有动作监督 |
| Michelet用途转换 | 床位需求解除后是否腾位置 | 允许移床并非强制移床；保留睡眠需求的对应条件缺失 |
| F-House靠边柜 | 在交流与保留家具约束下组织布局 | 仅共同交流条件进入专业监督；另一条件为研究者设定 |

对象表与目录的精确分组检出一组相同状态、不同阶段：Paper第08/10步。两者最近回执不同，四斜视图文件哈希不同，只有俯视图相同；它们不构成完全相同多模态输入。第08步有决定监督，第10步没有。V1人工注释误称Paper阶段初态不同，V2据实际分组纠正，原版结果与源码保留。不能声称“零条件对照”，也不把精确相同场景作为所有专业样本的必要条件。

## 已做的数据修正

原44份文档共享六条知识，其中scope包含“First cabinet addition anchors…”和“Source rationale attached…not preparatory chair relocation”等实验编排信息。它们不是原专业原则。改动目标D/A的泄漏测试无法发现已经拷入输入的编排文字；不过两组同样可见，不能据此断言某组作弊、发生测试项目泄漏，或解释为失败的已证原因。

`audit_v2/KNOWLEDGE_CANDIDATE.json`仅保留原有decision_id、condition、principle；移出的scope完整保存在`KNOWLEDGE_METADATA.json`。该导出没有接入历史训练；后续 CHOICE 识别诊断已首次将它用于推理输入。场景自身的未知项、使用限制和来源许可账仍须保留，删除scope不能替代来源审核。

`CONDITIONAL_COMPLETIONS.json`将以下应用记录连到已有原生回放、动作、五图及来源证据，逐项哈希已核：

| 候选 | 条件与决定 | 后果及限制 |
| --- | --- | --- |
| Paper第09步 | 访客预留阶段结束，恢复同一桌的日常位置，随后归位坐凳 | 第10步才恢复两声明餐位；将失去空置预留区；旧坐凳扫掠有沙发冲突，不能标为完整物理搬运正例 |
| Waterloo第03步 | 共享阶段结束，分开第二桌，随后归位椅子 | 第03步两种完整模式均不通过，第04步独立工作模式通过；固定接近点保持，尺寸扰动、人体与搬运限制保留 |

这是依据已有原则补充的**研究者应用注释**，不是新发现的设计师原话或历史操作。新增来源原则0、项目0、动作0；两条尚未编码/训练，没有独立专业正向标签。不能通过重复命名夸大样本量。

## 与模型结果的关系

旧STRUCTBASE已记录12/12格式有效、12原生分派、5次状态变化，但终态仍有1对网格接触、缺目录餐椅及接近损失。说明合法执行不足以保证设计成功；该案不同于本轮Pine/Milan，不能用于证明当前接口修订已有效，也不能定位失败为缺专业知识。

部署输入CPU检查144/144通过，最高16279/18432token，耗时41.36秒、退出0。只覆盖已记录的历史输入，不保证未来任何轨迹都在上限内；没有新增模型能力结果。

## 接下来的取舍

不再重复旧房间自由生成或继续扩充通用接口检查。本批将可用材料收敛为：六条去编排注释的知识、原22步执行证据、两条有正反活动阶段的应用候选。下一次训练方案必须说明这些条件变化怎样改变应选动作，并把允许的多种解、过程中的临时功能损失和最终房间代价纳入同一比较。原数据的少量决定位置和单序列示范不足以支持扩大训练；本批也不提出新增训练申请。

若后续进行候选比较，它只能诊断“识别方案”能力；不能用挑选现成方案冒充从需求生成完整房间，或把已暴露训练家族当独立测试。总体研究尚未完成。

## 复现与实际执行

`PROTOCOL.json`为CPU只读范围；`receipt/`、`receipt_v2/`记录两版核对，`candidates_receipt/`记录候选生成。三次均退出0，各约0.12秒。目录名称是标识，真实开始时间以receipt为准。V2仅修正Paper人工注释，输入和原始数据未改；版本哈希见STATUS。部署检查的实际命令与41.36秒回执位于前一SEENPROMPT目录的`deployment_budget_receipt/`。
