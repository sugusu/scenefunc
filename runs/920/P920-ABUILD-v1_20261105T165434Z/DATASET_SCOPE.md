# 来源理由与建设动作的对应范围

本批新增 AIR 的七次实际添加，并从既有 SBUILD 九次添加重新组织一份候选。原四更新训练与原 SBUILD 数据保持不变；没有训练新适配器。

两案各只保留一条有来源的原则作为理由目标：短住衣物的开放取用、紧凑住宅的集中储物与连续起居。具体坐标、家具替代、添加顺序和对回放结果的解释另存为研究者说明，不作为理由目标。普通步骤仅监督动作。

每组获得同样的十六个动作和两个理由目标。理由样本在两组中相同且都能看到其场景；配对组只在对应动作的上下文中额外看到理由。这里仍不是“分开组完全不知道案例联系”，而是一个具体的动作条件化对照。理由能支持策略与对象类型，不能单独证明某个坐标最优。

这是候选数据组织，不是训练收益。尚未对新的混合集合运行 tokenizer/Trainer 或核定更新预算；仅核实际状态、五图绑定、合法工具调用及两组字符串目标相同。后续训练需按真实受监督 token 与项目权重重新审定。

两案来源项目不同，但均使用相关的 6×5 米研究矩形壳及若干共同资产代理，因此不能视为两种独立空间分布，也不能代替独立测试。厨卫六件固定设施是输入；静态床、椅、柜等代理不验证坐席、容量、隐私、安装或人体使用。保留所有失败的接近点。

全部新家具实例由引擎创建；没有保留原项目家具身份、原设计师软件轨迹、专业独立评价或研究使用权已获确认的主张。
