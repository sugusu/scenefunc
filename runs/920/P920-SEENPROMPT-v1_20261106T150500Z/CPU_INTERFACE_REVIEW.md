# 统一输入候选：CPU验收，不是新的学习结果

本次完成现有训练/部署输入的共同生成器及真实处理器核验。模型调用、优化更新、场景编辑均为0；已结束的12房间试验及4次seen-prompt调用没有重跑。主试验尚无专业决定监督收益的结论不变。

见`CPU_INTERFACE_CHECK_v2.json`及`CPU_INTERFACE_ENCODING_v2.json`；完整生成请求在服务器runtime目录，清单有逐项哈希，可由脚本重新构建。

`edit_request.py`明确区分当前家具与历史、来源资产与调用资产。仅提供move文字签名的十条旧样本仍只提供move，没有偷偷开放添加/删除。任务特有的“只能移动哪些家具”限制保留原文；除immutable外没有新增通用语义约束执行器，因此schema通过不等于任务合规或设计正确。

`edit_supervision.encode_request_targets`使用共同请求，并仅从官方加载器取得助手目标格式。它未接入历史训练入口，未修改已完成试验，也未产生新的权重。无决定的样本没有隐藏的未监督think前缀；有决定的七个位置保留原决定目标。

## 失败与修订

首版JSON输入检查通过，但后续编码入口先因导入顺序退出（4.28秒），修正导入后遇到原16,384 token上限（16.78秒）。两次日志保留在`interface_encoding_receipt`和`interface_encoding_receipt_v2`，不是模型失败。

候选V2只压缩JSON无意义空白，不删字段、值、知识或视图，也不扩上限。V2输入检查2.72秒、编码18.63秒，均退出0。首版生成器按原哈希保存在`cpu_code_archive/edit_request_v1.py`；V1请求和结果保留。真实seen-prompt运行仍因其校验器错误停止在4/6调用，与本次CPU修订分开。

## 对研究的含义与下一步

这解决了一个可确认的训练/部署表示差异，使后续比较可以使用相同输入入口；没有证明该差异造成此前失败，更没有证明修复后模型会选对设计策略。六项目、七理由位置的专业监督覆盖仍然很小，不能用工程验收替代专业学习证据。

后续CPU部署编码已完成144/144，最大16,279/18,432 token，41.36秒退出0；见DEPLOYMENT_BUDGET.json。此检查只覆盖历史请求。任何后续推理仍需冻结有限调用范围；不补跑已停止的旧探针。后续比较应以已有完整房间的条件化用途取舍为问题，保留强检索基线、相同工具及代价测量。新训练仍须单独审定；目前不扩大adapter更新、换新房题目或增加案例来追逐正结果。
