# 保留训练材料的显存修订方案

上一版获批试运行在真实反向的检查点重算阶段OOM，完成0更新；该批已终止且保持原样。当前方案只将36层语言模型的检查点输入暂存CPU，在反向时取回，并增加逐微例进度/失败显存记录。模型权重精度、五视图、全部输入与监督token、损失权重、LoRA模块及更新预算不变。

**拟执行：** GPU0，分开/配对两组各2次更新，共4次；3来源决定、10相关步骤，每组每更新20微例/982监督token，来源等权。语言q/v共3,833,856个LoRA参数，底座与视觉冻结；BF16、SDPA、AdaFactor、非重入检查点。每组最多1800秒，外层3900秒，首错即停，无重试和自动扩预算。主存可用量不足16GiB则启动失败。

`PLAN.json`是唯一拟执行计划，`PROPOSED_COMMAND.json`给出完整命令；`APPROVAL_TEMPLATE.json`是false模板。之前的批准不匹配新计划SHA，实际调用门禁已确认拒绝；当前尚未获新训练批准。

实际完成的检查：

- CPU上两个小型随机Qwen3-VL，均包含五张合成图；32/48输入token、语言q/v LoRA、相同初态分别做原方式与暂存方式反向，共4次反向，0优化。输出、loss及每个LoRA梯度最大误差均0，底座/视觉无梯度，全部参数未改。用例是float32 CPU，不能据此说真实BF16/GPU已验收。
- AST核对表明数据选择、目标token、源权重、compute_loss和采样逻辑未改；原失败计划SHA不变，原输入编码哈希与新代码哈希通过。
- CPU检查5.334462秒/exit0；旧批准/false模板两个实际命令exit1为预期拒绝。没有加载原8B模型、调用GPU或生成训练适配器。

根据固定序列和4096维BF16隐藏状态，36层输入约2.7–3.3GiB，**这是尺寸估算，不是已测节省量**。模型其他引用、重算工作区及分配器仍可能导致OOM；CPU传输会增加时间。仅包裹检查点入口，保留其内部重算hook；不将整个模型的已保存张量统统复制到CPU。实现依据已核本机PyTorch2.8代码及[官方保存张量说明](https://docs.pytorch.org/docs/2.8/autograd.html#torch.autograd.graph.save_on_cpu)、[检查点说明](https://docs.pytorch.org/docs/2.8/checkpoint.html)。

本轮要验的是训练/保存机制，不是专业学习或新项目设计效果。真实GPU显存与时间尚未验证。新试验如获批准，无论成功失败都报告实际前向/反向/更新数；保存与同进程重载通过也不等于冷启动优化器恢复。

代码、CPU证据及方案当前在本地完成；按普通更新每小时合并的约定，等待下一关键节点或小时批次发布，不为每个诊断重复推送。
