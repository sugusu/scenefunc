## 内容复核与结论边界

图像组输出带 `<think>` / `<tool_call>` 包裹；清单组全部输出LaTeX风格的 `\\begin{json}`，都不是本轮约定的完整JSON对象。**仅因包装不符，不能推断回答内容全部错误。** 本轮没有事后修复解析器或提取分数重算主指标。

`ASSISTANT_REVIEW.json` 单独保存助手事后内容审阅及对应片段，不是独立设计师标签。例如15299图像回答凭空描述阳台，14678描述并不存在的卫生间，10555描述并不存在的厨房；这些与公开清单/色块核对。另一方面，514图像回答拒绝无依据打分并列出门、窗与家具未知，不能算作设计判断失败。若干输出把通行或舒适推断标为observed，证据不足；未知项列表确实普遍存在。两组之间的语义观察仅为探索记录，不能代替未成功的预定比较。

这次应停止，不加预算围绕同六图调提示。下一主线是把已取得的专业知识、评价资料和来源对应三维示范分别用起来：为已有AIR等重建决定明确合法监督内容和排除内容，补下一条预定训练来源的可执行决定。若以后使用此审图基线，应先在另一个开发例上确定与底座原生输出相容的读取协议，再冻结新批次；该接口工作不成为专业知识抽取或三维重建的前置阻塞。训练和独立整屋评估仍待单独审定。
