## 2. 停止控制与房间评分分离

前瞻解析器按下列规则验收，并保存原始 token、终止原因及解析过程：

| 输出 | 控制判定 | 房间判定 |
|---|---|---|
| 完整合法工具调用 | 执行并记实际回执 | 按执行后的完整状态量测 |
| 正常 assistant 内容、真实 EOS、没有工具意图片段 | 无工具结束 | 独立检查未满足项；结束本身不算成功 |
| 出现工具开头但 JSON/闭合损坏 | 解析失败，不当作完成 | 原状态保留，记录失败 |
| 达 token 上限、超时或未完成输出 | 未完成，不当作完成 | 保留状态与成本，不猜测意图 |
| 原位移动被拒绝 | 工具拒绝 | 即使场景通过，也不算学会停止 |

这比上游“没有解析到调用即结束”增加了明确的错误区分，是实验评价约束，不能宣称是上游原有保证。允许合法完成中的未知项；不要求模型声称整屋成功。三组均用同一个经过验收的解析器。旧 `<done>` 输出不按新规则追认成功。

## 3. 先闭合现有样本的输入—目标—执行关系

下一项具体交付是一个候选数据包及加载器报告，最多复用现有 24 条目标，不继续加来源或场景来稀释问题：

1. 对两条停止记录通过官方 loader 生成新目标；校验输入、图像和量测一致，目标不泄漏、提示和工具回执不受监督、正常结束 token 受监督。记录新旧 target/token/hash 差异，核全部 22 条工具目标未意外改变。
2. 对决定位置登记：专业来源支持的理由、研究者活动条件、重建对象、动作、已验证后果与未知。不能把六个归一化组称为六个独立来源项目；不能把研究者完成判断称为设计师示范。
3. 固定已有训练内条件检查清单，包括满足状态应结束、未满足状态应修改，以及同一起点在不同用途下应有不同选择。复用既有可测需求与真实状态，登记哪些选择存在多个可行解。
4. 每个编辑检查同时列出允许的完整动作序列和终态验收；参考动作的中间椅桌错位不自动判整条失败。模型可用其他合法策略，只要终态达到同样需求且不新增硬失败；精确坐标命中只作复现指标。

这些步骤为 CPU/已有证据工作。若需要额外原生回放，冻结单独有限预算并使用持续评测授权；不得偷偷重跑已有生成。完成前不申请模糊的新训练授权。

## 4. 下一次训练的门槛与停止规则

新训练启动前，必须先有可审阅的实际数据清单、官方加载器张量与掩码核验、逐组命令、固定最大更新数/时间/保存点和输入哈希，再按 Goal 单独审定。当前文件不批准训练，也不沿用已用完的八次更新预算。

拟合评价不能只看总 NLL。至少分别报告工具名、对象/资产、参数、停止控制的 NLL，以及自由生成的合法控制、要求保留对象、完整训练任务通过数。训练内六个固定条件检查作为工程准入：两种已经满足的状态均须合法结束；其余编辑状态须在预先冻结的轨迹预算内满足当前用途且不新增已测硬失败。数量和具体 ID 在下一数据包中冻结后才可执行；这些不是泛化测试，也不能因为未通过而无限增加更新。

任一学习组在固定预算内未通过训练任务准入，交付拟合失败与错误类型，停止该轮向独立房间扩展；不要把开发失败解释成“专业知识无效”。通过也只说明有资格做开发对照。底座即使不通过训练示范复现仍是完整的强基线，不能被筛掉。

开发阶段按完整房间终态评价需求满足、保留对象、其他用途副作用、返工与总成本。Waterloo 与此前讨论的 Pine/Milan 均不能称封存盲测。是否扩大项目与预算由开发结果决定：强检索足够则收束训练；两种微调相当则承认动作学习收益；联合有额外收益才补同材料机制对照及从未用于迭代的项目。

## 5. 当前可以与不可以推出的结论

可以：原总损失下降主要体现在序列化类 token；已有自定义停止接口与上游不同；既有训练尚未证明稳定完成条件化编辑。应减少这些混杂后再检验专业监督。

不可以：停止格式是失败的唯一原因；改格式必然有效；24 条样本足以支撑顶会结论；未精确复制坐标就没有专业能力；教师强制字段分解证明了参数学到了什么。新协议本身不是论文创新，仍需真实项目决定数据与独立房间收益。
