# 有来源的数据批次与真实加载器对照

本轮把已执行的来源对应记录整理成可比较的数据，未运行设计模型、增加场景动作或训练。六条既有知识被冻结用于对照；随后新增的三条知识不回填这次已冻结的数据批次。

[实际结果](LOADER_RESULT.json)中，两组每个监督 token 完全相同，八个共同样本所有张量相同；只有动作例的理由前缀不同。配对组/分开组未填充长度总计13639/13580，统一批次形状9×16384。等张量形状不证明真实计算量、优化预算或运行时间相等。

四次调用在原回放中顺序执行，本轮将它们聚合为一个程序目标，只配初态观察。它不是设计师历史操作，也不是四个有逐步观察的在线助手样本。其依据是来源引导的条件化局部几何收益；没有完整隐藏高柜、收纳容量、感知开敞或整屋专业质量标签。Bukit的九步混合结果没有被作为正向建设目标。

[程序清单](PROGRAM_MANIFEST.json)、[公共样本清单](BATCH_MANIFEST.json)、[解码目标](SUPERVISED_TARGETS.json)与[原始样本](episodes/)可逐项审阅。清单中的independent_project_families字段仅计六个不同登记项目家族，不能视作统计独立性已验证；来源之间的共同论文相关性仍保留。

两组都另有I→R理由实例，且都看得到项目状态，因此这里检验的是动作序列内的理由条件化。它不涵盖所有可能的“分开学习/联合学习”。主研究仍需比较同样真实的材料、足够强的提示与同知识检索，并在独立项目评价。错配只作辅助诊断：训练打乱与推理替换分别记，正确胜过错误不能证明专业设计能力。

[检索检查](RETRIEVAL_AUDIT.json)对Ono、Bukit查询各排除本家族后留下五条；一个虚拟未知家族查询留下六条。它只验证开发材料的确定性家族过滤，没有检索排序、模型表现或真实封存测试结论。
