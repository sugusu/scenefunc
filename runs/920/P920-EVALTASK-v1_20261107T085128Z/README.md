# 有来源的收桌／办公条件任务：实际参考回放

本批把“桌下收纳可移动茶几”落实为同一完整代理房间的两种用途参考。两份终态均已在 Scene-Designer 原生工具中执行、逐步保存并取得初末五视图；共 **6 次编辑、20 张图、0 次模型调用、0 次训练更新**。它解决下一学习比较的任务可行性缺口，尚未检验模型是否会选对做法。

## 来源与重建范围

[Julie Nabucet 与 Marc Baillargeon 的 Bien vivre dans 16m²](http://www.julienabucet.com/portfolio/bien-vivre-dans-16m2/)明确描述：带轮木制家具可以藏在书桌下，床半拉出作坐席时又充当茶几。完整溯源见 `SOURCE_RECORD.json`，四个候选来源的取舍见 `SOURCE_REVIEW.json`。

这里只迁移“移动桌具利用桌下空间”的决定。4×4×2.6 米房间、12 件家具组件、住户请求、尺寸、对象保留要求和动作顺序均为研究者设定；固定床与独立沙发不复现原项目的升高厨房和抽拉床。模型输入不能含参考位置或本页结果。一个来源族的两种条件不算两个独立项目；该族在派生前已排除训练和检索，但开发者看过来源和结果，不能称封存测试。原网页保留版权，公开包仅有归因事实概述和自行生成的几何代理，不含原图／全文，不准入训练。

## 实际终态交叉检查

| 状态 | 指定2.4m²中央区域完全清空 | 桌下膝部空间 | 凳位就绪 | 办公几何代理通过 | 中央区域占用m² |
|---|---|---|---|---|---|
| 共同初态 | 否 | 空 | 否 | 否 | 0.2160 |
| 收桌终态（2步） | 是 | 被茶几占用 | 否 | 否 | 0 |
| 办公终态（4步） | 否 | 空 | 是 | 是 | 0.3780 |

办公终态的占用含茶几和凳子，不能只计算茶几面积。两种条件没有同时要求清空中央区域和办公。模型将来可以找到其他可行解；这两条参考不是唯一正确答案。

实际状态检查：无正体积包围盒相交、无越界，全部固定对象与实例身份保留。0.4/0.5 米方形身体代理可从入口到达床侧、厨房、衣柜和卫浴入口；**0.6 米代理在所有状态的卫浴入口均失败**。人体舒适、开门、柜容、厨卫真实功能、搬运力量与独立设计质量仍未知，不能宣布整屋可用。原生移动会扰动指定位置，最大坐标分量偏差约1.40毫米；结果按实际保存状态计分，没有用理想候选代替。

原始回放回执 `reserved_floor.scope` 留有旧通用脚本的“bed-space”标签；本任务数值边界明确指中央活动区，不是床展开或睡眠容量。原件保留，`SUMMARY.json`已作解释。

## 已保留的失败与执行成本

V1 初态卫浴代理重叠、凳子直线路径受阻，未做原生家具编辑即拒绝。`input_v2/REVISION.json`记录一次模型输出前的修订：淋浴代理北移5厘米、办公动作分段；任务、阈值、终点不变。沙盒第一次参考启动300秒超时，未建立会话、未执行编辑；随后按主机执行修订启动两条件各一次，分别111.516秒、111.062秒，均exit 0。不重抽模型、不追加训练、不删除失败。

## 可审阅产物与恢复

- `RESULTS.csv` / `SUMMARY.json`：按实际状态计算的交叉结果、视图哈希、检查点路径和误差。
- `evidence/*_RESULT.json` / `*_STEPS.json` / `*_state.json`：原生回执、动作、保存状态；`*_execution_receipt.json`记录真实命令、首日志、启动／退出时间与状态。
- `views/`：两次回放初末五视图。`VISUAL_REVIEW.json`为助手看图核对，不是独立专业评价。
- `input_v2/`：冻结任务、两条实际动作计划和三维导出计划。
- `evidence/EXPORT_*.json`：初态和两终态GLB的服务器路径、版本哈希与几何回读验收；每份41节点，最大边界误差9.54e-8米。权威可编辑状态是原生checkpoint，GLB仅预览。
- `RECOVERY.md`：原生环境、构建和恢复方式；参数数组保存在执行回执，不必重复原生执行来恢复交付。
