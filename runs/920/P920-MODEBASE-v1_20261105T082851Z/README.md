# 固定底座活动／知识基线：四次真实运行均未满足终态条件

本批冻结同一Waterloo研究重建的两种活动需求（分桌工作、合桌待客）与有／无同一来源知识，共四次独立会话。每例最多6次模型与工具调用，保留全部失败，没有重抽、训练或人工修订中间布局。来源知识来自上一条决定记录；本批没有新增专业知识或独立项目。

| 活动与知识 | 初态通过 | 终态通过 | 主要终态问题 | 模型／工具尝试 |
|---|---|---|---|---|
| 分桌工作，无知识 | 是 | 否 | 桌A与客凳A包络重叠；0.5/0.6m代理下4个固定接近点失联 | 6／6 |
| 合桌待客，有知识 | 否 | 否 | 两桌未合；桌A与工作凳A包络重叠 | 6／6 |
| 合桌待客，无知识 | 否 | 否 | 两桌未合；桌A与工作凳A包络小幅重叠 | 6／6 |
| 分桌工作，有知识 | 是 | 否 | 违反保留要求，删除两张客凳；该硬失败后用途未计通过 | 6／6 |

四会话实际stage exit均为0，原生工具23/24返回success；唯一false为首轮把桌A移到原位置的no_movement回执。它提示“换个位置再试”，可能影响无必要移动，但这一因果没有单独验证。进程完成、工具成功与设计成功严格分开。24次推理输入总173221token，输出995token；生成耗时96.889054s（不含加载/渲染），整批1127.328388s。三个会话只操作桌A；剩余会话还操作桌B、删除客凳并查询状态。所有原始输出、请求与回执见cases/。

知识组初始输入仅增加同一85token来源段；每活动去掉此段后请求逐字相同，初始五张图字节相同。后续轨迹和token量不同，不能称计算等量。五视图绑定53次核验、29份检查点逐文件核验。每例单一贪心尝试、同一个暴露的研究房间，不给统计显著性或跨项目结论。

本批已经明确要求分桌／合桌和几何阈值，测的是明确需求到动作的执行，不能证明从生活活动自主选择专业策略。输入没有参考坐标，但共享的几何和用途反馈直接给出当前代理条件是否满足。沿用官方消息布局，系统提示改为既有家具修订，和原SFT从生成资产开始的提示不同。不能把失败只归因为缺少专业知识，也不能由此断言配对训练必要或有效。原生系统允许无工具调用时结束，本批相同；四例都未主动停止。

初态本已满足工作条件，因此工作组终态通过也只能记为保持。缺少客凳的场景不能靠无包络重叠成为正例。桌凳包络相交不直接证明三角网格实体相交或真人无法使用；0.4/0.5/0.6m方形身体、2cm网格和门全开是研究条件。近同轴拼桌、固定尺寸桌面与四餐位代理之外的有效设计没有被此试验穷尽。最终专业整屋质量仍未知。

完整证据：PROTOCOL、INPUT_FREEZE、RESULT、PROMPT_SCOPE_REVIEW、EXPORTS、COMMANDS、SERVER_FILES。四个终态GLB各约3.55MB留服务器，路径和SHA在EXPORTS中；可编辑源为各rollouts/<case>/final_checkpoint。全部剩余视觉对象回读通过：前三例43节点，删凳例41节点。最终检查点核过文件，没有新增冷恢复。输入可用scripts/920/restore_mode_input.py按INPUT_RECONSTRUCTION恢复，实际33文件恢复检查通过，无模型调用。
