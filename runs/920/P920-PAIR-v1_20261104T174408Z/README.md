# 配对对照：实际目标预算核验

本次仅使用已标明非专业数据的工程样本，调用固定版本官方 StepwiseSFTDataset 和 StepwiseCollator。CPU 实际运行 5.8364 秒，退出 0，17 项检查通过；未加载模型权重、未执行样本家具动作、未训练。实际命令、启动时间、首日志和退出状态见 execution/receipt.json。

两组各监督一次同样理由和同样动作，目标 token ID 逐个相同。共同的理由样本包含相同任务、状态和五视图；动作样本只有配对组在工具调用前保留教师强制的本决定理由，该前缀不重复计入损失。理由样本屏蔽结束消息标记，避免教模型解释后直接终止。封装变化使本协议为 83 token，不能改写旧 DATA 实验的 84/92 实测记录。

这检验的是理由与动作在同一个预测序列内的关联；两组仍都能在理由样本中看到该项目状态。不能声称分开组完全不知道理由适用的项目。推理必须同条件，并由模型自行生成解释，不能提供测试设计师的事后理由。固定填充不证明实际 FLOP、显存或耗时相等；没有执行优化器，也未验收官方训练入口与此包装器的集成。

PLAN.json 在运行前冻结 180 秒 CPU、一个决定、零权重加载/训练和 20 MiB 输出上限。audit/RESULT.json 保留逐项结果和目标解码；MANIFEST.json 锁定输入和五张原有观察图。decision_pairing.py 只接受 audit_only 清单，不能绕过专业数据准入或训练审定。下一步须用可信同项目材料核对，并分别审定计算预算、基线及独立整屋评价。
