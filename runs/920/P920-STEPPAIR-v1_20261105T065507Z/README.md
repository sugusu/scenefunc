# 五步真实上下文的分开／配对加载器审计

固定官方训练入口的两次CPU dry-run均通过。STORAGE-v2的五次实际动作各自绑定当时的对象表、量测、五图及上一回执；没有把整段程序都配在第一张图上。两组均为十个样本、472个监督token，逐项目标ID相同；五个解释输入完全相同，五个动作输入确实因对应解释而不同。

**这是一个来源决定的五个依赖步骤。** 首步解释含有出处的收纳集中原则及研究者翻译，后四步是研究者的执行计划。不能说取得五条专业经验，也不能把这次数据接线通过当成模型学会设计。

## 对照实际改变什么

令 I 是当前需求、对象状态、量测、上一实际回执和五图，R 是该步解释，A 是该步实际动作。每一步均构造两个样本：

| 组别 | 解释样本 | 动作样本 |
|---|---|---|
| 分开 | I → R | I → A |
| 配对 | I → R | I → R（标签屏蔽）→ A |

配对动作中的R参与注意力，但不再次计入监督目标。两组都学习同一批正确解释和动作，不使用错配理由。两组的解释样本也都有当前场景，因此这里检验的是**同一序列中理由对动作预测的条件作用**，不能称分开组完全不知道项目与理由的联系。

原始候选保持不变。派生样本对两组一致移除了`task_context`中显式的`source_principle`字段，以免该字段在两组动作输入中重复提供原则；共同的未知项仍说明原项目技术墙与代理柜体的表达范围。没有移除全部相关知识，不能用本审计声称控制了全部知识关联。来源归属逐步见`SOURCE_ATTRIBUTION.json`。

当前量测是工具已得到的输入，既非事后标签，也非专业偏好。每步未来状态、实际后果及资格元数据放在`evaluation_only`，哨兵确认其不进入模型文本。当前对象表、完整测量及前一回执逐字段核对实际记录。第2、3步的暂时柜前损失保留在原轨迹，未给五步统一贴上“每步改善”的标签。
