普通方法不只会拒绝坏动作：已主动找到并执行两项局部修改

本轮完成一个实际控制实验：只用初始公开状态、任务区域和几何工具，普通搜索为两项开发任务找到操作；随后通过固定版本的原生移动函数执行，并重新运行原版基于 SDF 的评测器。没有新增模型推理、训练或付费 API。它改变了下一步判断：这两个已知任务目前不足以支持扩大判断机制训练。

12条历史模型轨迹只有同一房间的两种不同任务输入。这里是2项开发任务，不是12个独立场景。家具原本就是研究者构造的方盒代理；本轮没有将真实家具替换成方盒，也没有生成新的用户房间。

这次算法实际做了什么

候选按固定顺序来自公开目标区域中心、避开禁入区域的最小轴向移动，以及房间内9×9位置格点。对象轮流获得候选预算，保留原朝向。每项任务最多128次终态评估、最多两步联合编辑，最终验收相对于初始状态。搜索没有读取旧模型提议、后状态或教师动作。两次都在第一层找到结果，所以不能称为已经验证了多步搜索能力。

除已有功能与包围盒检查外，候选还排除新增墙体相交。这个普通安全条件单独记录，后续各方法应共享；不是偷偷修改旧实验分数。搜索程序与预算在运行前保存，但它们是在看过开发失败后设计的，不能称为独立测试。

原生执行与资源恢复

第一次恢复在缺少 room.sdf 时失败，零次移动，日志保留。随后使用固定 Git 版本的原始构建器、原始第二版几何输入重建资源，只重定位输入文件路径。重建后的全部原生状态与保存的初始状态逐字段一致，没有给新搜索提供旧可行解。

两次选中操作实际调用了原生公开移动闭包、移动实现及 RoomScene 状态更新。方法体未改，跳过了不需要的 SDK 服务启动和循环检测初始化；摆放噪声明确设为零。它是原生移动内核执行，不是完整 Scene-Designer 会话。随后原版任务评测器读取重建的 SDF 与实际后状态，初始分数、预测分数、执行后分数全部一致。

没有渲染、物理模拟、搬运轨迹或人体使用验证。SDF 中的家具本来就是12个程序化代理，类别、舒适度、材质和真实功能不能由这次通过推断。

对研究主张的影响

此前已有证据说明普通工具可以预测坏动作；现在又有证据说明普通候选生成可以主动找到合格局部修改。因此不应再把这两项失败当成学习型判断机制不可替代的案例。仍不能与旧模型运行直接宣称公平的速度优势：旧模型没有使用相同候选器，当前控制也没有承担视觉推理或完整生成成本。

若继续比较“先判断，再行动”，需要区分两个普通训练目标：CE(D|X)+CE(A|X,D) 与 CE(D|X)+CE(A|X)。前者在推理时必须生成自己的判断，后者可以直接行动。Distilling Step-by-Step §3.2已经提出理由的辅助多任务监督；Scratchpads也早已研究输出中间计算。不能把这两种结构之间的比较本身命名成新算法。

一个明确的理论边界是：固定模型参数后，若判断文字仅由当前输入与独立随机数产生，没有查询新证据，则它没有给当前环境增加独立观测。它仍可能通过额外计算帮助有限模型，但收益必须在动作、完整要求和总成本上检验。相同监督不等于相同计算；直接动作组应被允许把省下的判断成本用于搜索，不能要求它生成一段无用文字来人为拖慢。

详细的条件、推导、成本对照及不能支持的主张写在 算法与理论审查。这些是识别实验解释边界的分析，不是新定理，也不证明整个三维 Agent 方向无效。

下一步投入判断

保留这套已执行的普通强对照，不为这两个已知代理任务扩大训练或开启 GPU。若继续候选判断机制，应转到未参与制定这些规则的任务族，共享几何预检、候选操作与预算，并回到完整生成的资产和关系要求。当前主机观察格式仍存在 append_v1 与版本化材料的接入差异，需要明确选择后再比较，不能把格式差异误认成方法差异。

这不改变总目标，也不表示研究完成。当前没有足够证据承诺 CVPR 级贡献；同样不能由普通方法在一个小任务上成功，推出三维生成不需要学习或智能体。
