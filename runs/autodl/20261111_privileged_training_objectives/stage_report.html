1. 新近邻使哪些算法主张必须收紧
On-Policy Context Distillation for Language Models（OPCD，arXiv2602.12275v1）已把经验知识/系统指令作为教师额外上下文，学生在无该上下文时采样，再向上下文教师蒸馏。不能把“把设计知识教进参数，部署不再读长文”单独作为新机制。
Instruct, Not Answer（arXiv2609.32201v1）实际比较一般性错误修正规则与逐题答案特权，且用前向KL、完整词表、无裁剪。论文在逻辑形式化任务上的结果不是三维证据；它说明“一般指令比完整答案更适合迁移”已有直接实验前作，不能重新命名为设计原则学习的算法创新。
ECOS（arXiv2611.12232v1，2026-11-09公开）已经用实际环境结果调节技能教师的命令监督，并给生成反思/技能的角色分配回报。把环境反馈、技能生成、命令mask和共享模型联合训练，均需要列为已有机制。

2. 采样方式与KL方向是两项独立选择
用h表示学生实际可见历史，c表示教师额外上下文，p_c为教师下一token分布，q为学生分布。
“On-policy”指用于评分的生成前缀来自学生，不自动规定优化KL(p_c||q)还是KL(q||p_c)。OPCD方法式写后者；Instruct正文§4明确使用前者。不能因为二者都称OPCD就把训练式混成一个。

本轮固定微软LMOps提交6f53ef41c951de0962bbf27fe3f5819eabc8ce0e，实际读取并调用其未经修改的kl_penalty定义；没有import整个VeRL、启动Ray或实例化语言模型。该核以第一个分布为权重计算sum p(log p-log q)，调用者交换参数会交换方向。dp_actor的on_policy_merge分支确实决定参数顺序。来源代码：
https://github.com/microsoft/LMOps/tree/6f53ef41c951de0962bbf27fe3f5819eabc8ce0e/opcd
仅凭函数名、配置名full或文中一个KL词，均不足以确认实际目标。

3. 完整KL、截取部分和与条件化KL不等价
对完整规范化分布p、q和固定索引子集I，定义：
  K_full = sum_all p_i log(p_i/q_i)
  K_part = sum_(i in I) p_i log(p_i/q_i)
  K_cond = KL(p(.|I)||q(.|I))。
K_full与K_cond非负，但K_part可以负；K_cond也不等于K_full。负的部分和可以是优化代理，并不因此证明原论文训练错误；只是不能给它直接套用完整KL的非负性或完整轨迹KL界。

实际读取的math_consolidate.sh默认KL_TOPK=256、KL_RENORM_TOPK=False，均可由参数覆盖。ray_trainer同时支持学生Top-k与可选双方索引合并。本轮没有取得作者每次实验的实际覆盖参数，不能说论文全部结果必定用了某一条分支。

CPU调用原始核的一个数学见证：p=(0.6,0.3,0.1)，q=(0.7,0.2,0.1)，I={0}，得到：
  K_full约0.02914912；K_part约-0.09249041；K_cond=0。
这些数字来自人为指定的概率向量，不是模型logit、动作、偏好或房间质量。另一个正概率向量也作了同类核查；两项均保存，未选取生成任务来制造结果。

若要一个保留尾部总质量的标准比较量，可把所有未选项合为一个类别：
  p_T=sum_(i not in I)p_i，q_T=sum_(i not in I)q_i；
  K_bucket=K_part+p_T log(p_T/q_T)。
链式分解给出：
  K_full=K_bucket+p_T KL(p(.|T)||q(.|T)) >= K_bucket >= 0。
这是标准KL分组/数据处理性质，不是新蒸馏算法。本轮独立标量计算核对了该恒等式，但没有把尾桶接到训练宿主，也没有测量其是否提升任何三维策略。若论文目标是完整词表KL，就应明确计算完整词表，或明确报告代理和尾部覆盖，不能悄悄换分母。

4. 教师看得到、学生看不到的信息不能靠换KL方向自动恢复
这里只分析一个固定学生观察h与一个token/有限动作分布，不主张求解整个自回归或闭环目标。设不可见教师上下文的条件分布为mu(c|h)，各p_c严格为正，学生可自由选择同一q。
教师分布在这项分析中固定且不反传；这里的最优点也不是共享自教师持续更新过程的全局收敛结论。
  min_q E_c KL(p_c||q) 的解是q_F(a)=E_c p_c(a)。
证明：与q有关的项是-sum_a E_c p_c(a)log q(a)，其余为常数；交叉熵的最小点为这个算术混合分布。
  min_q E_c KL(q||p_c) 的解是q_R(a)∝exp(E_c log p_c(a))。
证明：令g(a)=exp(E_c log p_c(a))，Z=sum_a g(a)，则目标等于KL(q||g/Z)-log Z。

当不同c要求不同偏好时，两者可以选择不同分布。本轮用两个明确声明为人造的三项分布核对解析解，在对应logit上只计算梯度：最大绝对值在1e-16量级，没有optimizer.step，也没有神经网络对象。这个见证不说明哪种行为在真实任务更好，因为并未赋予任何真实功能回报。

若c可由h可靠确定，则mu可退化，上述信息不对称结论不能被拿来否定蒸馏。若c只是一般规则、而h已含当前用途/几何信息，有限模型仍可能通过训练学会更有效地处理它们。相反，如果c包含未展示的几何结果、未来资产或答案，不能用教师高置信度证明学生已经具备取得这些证据的能力。允许查询工具时应真实执行查询并计成本；这是信息获取动作，不是口头增加一个“检查”理由。

5. ECOS提供了什么，不能直接搬来什么
ECOS每任务采8条轨迹，生成逐轨迹反思和一个合并技能，预更新模型在相同学生理由前缀下，用技能有无造成的token log概率差delta评分。
它以冻结表示聚类观察，要求可接受动作集合相同，构造经验转移图，经过Bellman迭代、GAE和组内标准化得到命令优势。它不是对单条工具success直接赋分，也不是已经证明的真实反事实Q函数。

其命令调节为m=1+alpha sign(mean(delta)) tanh(A/kappa)，权重为命令mask*m*delta。m非负，只改变监督强弱，不反转各token自身的方向。命令mask不包含理由，但主GRPO目标仍覆盖完整响应；不能概括成“模型不再学习思考”。反思/技能的额外credit是组内、状态中心化的优势与原始命令概率差的加权协方差，并通过另一个损失训练分析角色。

一项明确的适用边界：若整组每条记录的环境reward都为0、终止/截断值为0，则初始化值、Bellman备份、TD与GAE均为0；标准化辅助优势为0，m=1，分析角色credit为0。此时校准部分没有产生新的环境信息；蒸馏本身和其他正则仍可能更新。不能把这个条件扩大成“所有终局失败的任务都无信号”，因为失败任务仍可能有局部reward或无效动作罚分。

还不能把该方法的ALFWorld/WebShop指标当三维收益。它使用文本交互、特定动作空间、任务回报、反思/技能SFT初始化与在线采样。当前未取得其可运行官方实现，本文中的方程审阅不是完整源码复现。

固定教师与单位置下，还可以说明未调节log概率差与反向KL的一阶联系：令delta(a)=log p(a)-log q0(a)，从q0采样并以它为常量，未裁剪代理L=-E_(a~q0)[q_theta(a)/q0(a)*delta(a)]在theta0处的梯度等于KL(q_theta||p)的梯度；归一化使sum_a grad q_theta(a)=0。这个关系要求全支持、固定教师和精确期望；加入命令mask、m、裁剪和有限样本之后，是不同的代理，不自动等于整个闭环轨迹KL。这同样是普通的局部梯度推导，不是ECOS或本项目的全局收敛保证。

6. 三维原生接口的一个实质差别：一次主策略输出可有多个命令
重新读取已核验的19条主策略决策和35条工具结果，按原packet和batch_index核对：10个响应含1条命令，5个含3条，2个含4条，1个含2条，1个无命令。共有8个多命令响应；其中17条命令前面还有同批命令。
在这个宿主中，主策略一次先生成整个有序批次，之后工具执行并回传；工具内可以另有VLM调用，但不是主策略在同批每条命令之前获得了新观察。原生动作分布应写为：
  pi_theta(a_1,...,a_m|h)=product_j pi_theta(a_j|h,a_<j)。
各项还可依赖前面已生成的理由token；a_<j不包含尚未回传的执行结果。工具状态则顺序更新s_(j+1)~K(s_j,a_j)，不能把执行后看到的s_j冒充主策略当时已获得的h。

因此，若迁移命令级优势和教师mask，需要同时区分生成前缀、执行顺序和反馈暴露点。原生工具schema相同也不等于两个状态拥有相同的有效连续位姿/对象操作集合，不能把工具名列表直接替代ECOS的可接受动作集合条件。按命令切开token只是训练接口，未解决状态等价、回报正确性与信用分配。
本轮native_batch_contract.json保存每条命令的批次位置和证据来源。这是由旧轨迹派生的适配材料，不是新轨迹、新专家标签或收益。

7. 对现有数据和候选机制作出的具体决定
旧原生记录仍是一条部分完成的轨迹，35项工具记录的expert_correctness和complete_scene_success全部未知。它既不是8条采样组，也没有合法的环境命令优势；本轮没有用工具success造出这些标签。24个局部重建单元及8个来源原则关联也不因新论文而升级为专家完整轨迹。

保留的候选仍为：在相同用户要求、真实观察、来源知识和工具下，学习有条件的设计决定D，再由自己的D生成原生动作。它的普通加权SFT、连续CoT、AUX不读D、阶段提示与去来源/只计划条件，仍是必须对照的同信息路径。本轮不把该候选悄悄改成“无需专家的全GRPO已准备好”，也不将标准KL尾桶和ECOS改名为新方法。

对后续实验，先需要验证的是额外来源或反馈是否真的使教师更好地选择可执行动作、且这项改进不是普通提示/API语义规则/现有搜索解释的。教师上下文要分成一般接口规则、可迁移的来源知识、当前观察的派生摘要和本实例未来证据四类；不把它们合在一个“有记忆”条件。部署比较按实际可得信息设置，额外来源给所有同信息强基线；真值/未来信息只作明确的教师条件，不进入测试策略。
学习目标比较应分别固定采样、KL方向、词表/尾部、mask、教师参数生命周期、更新次数及总费用。若本轮只比较上下文作用，就先固定学习目标；若比较目标，则保持教师信息与rollout来源相同。训练目标改变与设计知识价值不能同时混入结论。
