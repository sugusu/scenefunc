同材料还不够：需要明确模型当前要输出什么

本轮实际编码时间：2026-11-09T17:51:06.646024+00:00。来源固定在 runs/920@75fc783；没有改动旧实验、调用模型或启动训练。

上一轮确认了 separate 与 paired 的目标材料相同，本轮进一步发现：原 separate 的 8 个理由样本与对应动作样本使用完全相同的输入，却在首 token 上要求不同输出。它可以作为一种无任务区分的混合监督，但不能直接替代明确区分任务的强多任务对照。应修订上一轮“准备好的 separate 可以直接检验配对作用”的建议。

1. 事实与推断分开

从固定 Git 读取全部 24 个样本的两组原文，使用与原训练计划哈希相同的本地 tokenizer 重建 48 份目标序列。全部动作和理由 token 与原 MATERIAL_MANIFEST 的哈希一致；没有加载模型权重或远端训练张量。

在 8 个存在理由监督的样本中，同一输入前缀分别监督 <think>（token 151667）与 <tool_call>（token 151657）。数据加载器未添加任务标记。paired 的动作损失则在完整理由之后计算，因此没有这处同前缀的两任务竞争。

这不是说“一种输入不能对应多个合法输出”。模型可以学习混合分布。问题是：若 separate 推理时生成了理由，它没有在该理由之后受到动作续写监督；若直接生成动作，又不是同一条推理链。比较结果会同时受到任务选择、续写条件与空间知识利用的影响。

这个因素目前只影响对未执行的 separate 对照的解释。已发布的旧实验没有运行这组材料，不能用本发现解释其 0/2 修复，也不能推断修正后会提高场景质量。

2. 理论：增加了什么不可区分性

在某个相同前缀 I 上，设理由首 token 的权重为 w_D、动作首 token 的权重为 w_A。忽略其他 token 及参数共享时，两项交叉熵为：

L_start = -w_D log p(think|I) - w_A log p(tool|I)
p*(think|I) = w_D / (w_D + w_A)
min L_start = (w_D+w_A) H(w_D/(w_D+w_A)).

项目按家族与组件 token 数归一化，因此 w_D=1/(6N_D)、w_A=1/(6N_A)，概率为 N_A/(N_A+N_D)。8 个位置的这项最低加权损失合计 0.006725769。这是局部目标的解析性质，数值很小；不代表实际模型的分支概率、总损失、训练稳定性或功能成功率。其作用是指出对照中多了一个因素，而非宣布发现训练失败的唯一原因。

给两项任务明确不同的输入标记后，不再要求同一个条件分布同时兼顾这两个首 token。paired 与 separate 随后仍可能存在真实差异：动作是否读取理由、读取的是教师理由还是部署时的模型草稿。这些应分别记录，不能用训练损失的降低代替真实执行收益。

3. 已实现的普通强对照

实现位于 scripts/autodl/audit_material_routing.py，已经逐样本运行。两组都使用相同的任务标记、原始场景与五视图路径；只在 paired 的动作阶段增加理由前缀。保留全部原目标 token 和家族权重，没有增加新的专业决定或坐标答案。

条件理由任务动作任务
separate_taggedp(D|I, DECISION_RECORD)p(A|I, SCENE_ACTION)
paired_taggedp(D|I, DECISION_RECORD)p(A|I, SCENE_ACTION, D)

每组仍为 32 个监督组件，1643 个动作 token、1332 个理由 token。paired 多读 1332 个理由前缀 token；输入任务标记也有成本，不能声称总算力完全相同。理由任务沿用原闭合标签停止，不加入新的 EOS 监督。终止样本仍属于动作／控制目标，不冒充专业理由。

部署时 paired 只能读取模型刚生成的决定草稿，不能从评测答案检索教师理由。为了分离额外计算，应同时保留“两组都生成草稿，separate 丢弃它”的等调用比较，以及 separate 直接生成动作的低成本结果。任何失败草稿、未闭合输出与超限都计入预算；不能免费反复重试。实现中的 action_prefix 接口区分这些边界，但本轮没有运行推理循环。

本轮检查的是文本模板、分词边界、目标哈希与观察内容保持。完整多模态像素展开、label mask 接入实际 Trainer、部署两阶段协议和独立场景结果仍未完成，training_ready=false。不把这批材料称为已验证的学习方法。

4. 直接相关的已有方法

Distilling Step-by-Step（ACL 2023）已用理由与标签作多任务监督，并明确通过任务前缀区分输出。官方固定代码的 run.py使用 predict: 与 explain:，model_utils.py分别前向后加权损失。因此，这次任务区分修正属于普通强基线建设，不构成三维算法创新。

5. 与实际场景失败的关系

重新查看 MATCHEDROLL 原始审阅与解析记录，确认 35 次输出中 24 次结构拒绝、9 次合法终止、2 次工具调用；2 次调用里只有一次改动，且引入损害。旧报告已公开这些事实，本轮不把重复统计包装为新实验。后续在第一次解析路径分歧后的输出依赖原来的反馈，不能离线拼接成另一种 Agent 成绩。

因此当前有两个独立问题：旧结果存在解析／执行与需求判断混杂；拟议同材料对照还存在任务区分因素。解决它们能让下一次实验有解释力，尚不能证明空间推理会提高。上一轮普通几何已解开的 Paris 案例也不能变成这套训练的效果证据。

6. 下一次投入应回答的研究问题

可检验的窄问题是：在同样的场景证据、目标材料、工具与预算下，显式决定记录供动作阶段读取，能否改善实际要求完成，并超过带任务区分的普通多任务学习？如果只改进格式、停止或复述原则，收益应归到相应层面。只有在未参与开发的房间中改善完整生成／编辑结果，才有依据讨论更大的三维贡献。

这不是已经确定的 CVPR 方法。当前没有必要为本轮准备开启 GPU；下一步先完成多模态与部署协议的一致性，再结合已有运行的完整结果决定是否值得有限训练。不能仅因这个普通修正完成，就继续扩大样本或模型规模。
