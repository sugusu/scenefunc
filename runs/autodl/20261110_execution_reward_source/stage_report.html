执行奖励不能代替内容目标：新近方法与源码边界

Video-Coder，2026-11-06，v1已把代码执行反馈、最终内容奖励和奖励退火用于三维场景代码智能体。其终点是视频，不能据此声称解决完整可编辑室内场景。当前阅读为定向方法、配置与奖励分支，没有运行其系统、训练、视频服务或付费评价。

已核对的分支

固定源码提交0d87088df3c6ffeafd352b0afd94201de10375df。task.py完整阅读；video_reward.py阅读配置、标量奖励、门控、解析及score_rollout流程。奖励把环境接受与内容分数分开，accuracy字段记录接受状态。缓存跳过分支也返回1；这只是代码事实，未证明论文评测实际走过该分支。

发布配置调用独立生成器和外部VLM评价，评测失败默认抛错。我们没有启动这些服务。不能用本地工具返回success替代完整要求；也不能把外部评分失败当作场景语义失败而不报告。

可确定的奖励推导

同一固定组内，全部接受且未触发faithfulness门控：
R_i = λ + α r_i, α>0
R_i−mean(R) = α(r_i−mean(r))
A_i = (r_i−mean(r))/std(r)  （非零标准差，无epsilon）

因此λ在该组的归一化优势中抵消；固定epsilon也不改变λ的抵消。混合接受/门控组、后续策略分布及采样会改变，所以这不证明退火整体无用，也不是新的定理。它要求我们的对照分别记录执行结果与内容完成，不能只解释一个汇总奖励。

论文方法段与实验段的样本数量不一致；仓库与论文的训练配置也有差别，当前不选一个数字当作已核实规模。未完整审阅最终复执行的harness实现。源码仅本地保存，下载的许可文件失败，不把未确认许可的源文件放入公开包。
